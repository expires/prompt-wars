# Project brief: prompt-wars

Written by the Architect during `agents init`. Keep it short and factual.

## Purpose
Multiplayer browser FPS where players type a prompt and an LLM generates their weapon.
The server balances every generated weapon (`clampWeapon`), and the client renders its model
from a library of 1040 procedural parts.

## Stack
- pnpm workspace (pnpm 10, lockfile v9), TypeScript everywhere, ESM.
- `server/`: SpacetimeDB 2.10 TypeScript module (tables, reducers, `generate_weapon` procedure).
  Route: `backend`.
- `shared/` (`@ai-gaem/shared`): weapon schema, balance (`clampWeapon`), presets, net constants.
  Bundled into both server and client. Route: `backend`. Tests use vitest.
- `parts/` (`@ai-gaem/parts`): procedural Three.js part library, recipes, `assembleWeapon()`.
  Route: `frontend`. Tests use vitest.
- `client/`: Vite + Three.js + Rapier. Has a `NetClient` interface with `SpacetimeNetClient`
  and `OfflineNetClient`, a DOM HUD, and Playwright e2e in `client/e2e/`. Route: `frontend`.

## Conventions
- See the `conventions` and `testing` skills.
- Commits: `feat(agent): ...` (the runner adds this prefix).

## Definition of done
- Every verify command passes: frozen-lockfile install, typecheck + vitest for shared and
  parts, server typecheck, client build (`tsc --noEmit && vite build`).
- Each acceptance criterion on the card holds, and nothing outside the card's files changed.
- Any change to balance or schema logic in `shared/` comes with vitest coverage.

## Protected paths
- `client/src/module_bindings/**`: generated by `pnpm --filter @ai-gaem/server generate`.
  A card that changes server tables or reducers must say that the bindings need regenerating.
  Workers never edit them by hand.
- `server/src/catalog.generated.ts`: generated by `server/scripts/sync-catalog.mjs`.
- `.agents/**`, `.env*`, `.vscode/**`.
